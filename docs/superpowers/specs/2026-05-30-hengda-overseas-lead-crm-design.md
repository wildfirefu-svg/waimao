# Hengda Overseas Lead CRM MVP Design

## Goal

Build a local web MVP for Qinhuangdao Hengda Fiberglass Co., Ltd. to manage overseas customer development for fiberglass yarn and fiberglass fabric.

The system should help users collect qualified leads, classify product fit, generate English outreach drafts, send single emails through SMTP, record follow-ups, and prevent repeat contact with unsubscribed leads.

## Confirmed Decisions

- First version is a local web app.
- Data model should preserve fields needed for future multi-user use.
- Target markets are USA, Europe, Middle East, and Southeast Asia.
- Product scope is fiberglass yarn and fiberglass fabric.
- Email sending uses SMTP server `smtp.zmail300.cn`.
- First version supports single-email sending only.
- No bulk sending in the MVP.
- Email draft mode supports both fixed templates and AI generation.
- If no AI API key is configured, the system falls back to template-based drafting.
- The operating interface is Chinese.
- Customer-facing email content remains English.

## Non-Goals

- No automated web scraping in the MVP.
- No bulk email campaigns.
- No automatic repeated follow-up sending.
- No CRM permissions workflow beyond preserving future `owner/user` fields.
- No claims about certifications, production capacity, technical parameters, or famous customers unless entered and confirmed by the user.
- No automatic sending to unsubscribed contacts.

## Users

The first user is the business owner or a single salesperson using the system locally.

The database should include ownership fields so the app can later support multiple salespeople without changing the core customer and email records.

## Core Workflow

1. User adds or imports a lead.
2. User records company name, country/region, website, email, industry, source URL, and notes.
3. System or user assigns product fit: fiberglass yarn, fiberglass fabric, or both.
4. User opens the lead and generates an English email draft.
5. If an AI API key is configured, the draft can be generated by AI using lead context and approved templates.
6. If no AI API key is configured, the system generates a draft from fixed templates.
7. Before sending, the system checks required compliance fields.
8. User sends one email through SMTP.
9. System records send status, sent time, and follow-up date.
10. If the contact unsubscribes, the user marks it as unsubscribed and the system blocks future sends to that email.

### Email Drafts

Drafting and review page for one selected lead.

Capabilities:

- Choose template type based on lead industry.
- Generate draft by AI if configured.
- Generate draft by template fallback if AI is not configured.
- Edit subject and body before sending.
- Save draft without sending.

Required checks before sending:

- Lead has an email address.
- Lead has a source URL.
- Lead is not marked unsubscribed.
- Email body contains unsubscribe language.

### Follow-ups

Page for reviewing leads that need manual follow-up.

MVP behavior:

- Show next follow-up date.
- Show current status.
- Let user generate first follow-up or final follow-up draft.
- Do not send follow-ups automatically.

## Email and SMTP Rules

SMTP settings are configured by the user. The known host is `smtp.zmail300.cn`.

The app should not hard-code the SMTP password.

Before sending an email, the app must:

- Verify the lead is not unsubscribed.
- Verify the email has unsubscribe text.
- Save the draft.
- Send only the selected single email.
- Record success or failure.

If sending fails, the system should show the error and keep the draft unsent.

## AI Drafting Rules

AI generation must use only known or user-entered facts.

The AI prompt should explicitly forbid inventing:

- Certifications
- Production capacity
- Export countries
- Famous customers
- Technical parameters
- Lowest price or best quality claims

If product specifications are blank, the generated email should ask the customer for requirements instead of providing numbers.

## Compliance Guardrails

The MVP is not a legal compliance system, but it should enforce basic operational safeguards:

- Keep lead source URL.
- Keep unsubscribe state.
- Block sending to unsubscribed contacts.
- Include unsubscribe language in outreach emails.
- Warn when contacting Europe-region leads.
- Avoid misleading subject lines and unverified claims.

## UI Direction

The interface is a Chinese business dashboard for daily salesperson work.

The approved UI direction is represented by:

- `docs/hengda-mvp-wireframe.html`

Design characteristics:

- Left sidebar navigation.
- Dense lead table.
- Metrics cards for lead and follow-up status.
- Right-side email draft panel.
- Compliance checklist before sending.
- Follow-up activity panel.
- Customer-facing email body remains English.

## Verification Plan

During implementation, verify:

- App starts locally.
- Lead can be created and edited.
- Product data can be created with blank optional fields.
- Template fallback can generate an email draft.
- AI mode falls back to template mode when no API key is configured.
- SMTP settings can be saved without hard-coding secrets.
- Single-email send is blocked for unsubscribed leads.
- Single-email send is blocked when unsubscribe language is missing.
- Successful send records a contact event.
- Follow-up date appears in the follow-up view.
